# CLAUDE.md

Notes for Claude Code working in this repo. The README is the user-facing feature list; this file is how the code and the release process fit together.

## Project

- Deakrix Riftbound Tracker: Windows desktop app for the Riftbound TCG (collection, wishlist, decks, prices, sales, borrowed cards, stores, booster sim "Dopamin").
- Made by Stefan (GitHub `Goodplayer01`). The app icon is his Bengal cat Dante.
- Riftbound only. Don't add other card games or make things generic for other TCGs.
- Stefan writes German. Answer him in German. Code, comments, commit messages and the README stay in English. The app UI is German and English (`src/i18n.ts`, German is the default). German texts keep Riftbound game terms in English, the way German players say them: Battlefield, Unit, Spell, Gear, Legend, Champion, Rune, Might, Energy, Trash, Showdown, keywords, and so on.

## Stack

- Electron 44 + React 19 + Vite 7 + TypeScript. Windows NSIS installer via electron-builder, auto-update via electron-updater from GitHub Releases.
- `electron/main.cjs`: window, updater, IPC (`net:fetchJson`, `net:fetchImageDataUrl`, `shell:openExternal`, `clipboard:writeImage` for the deck share image, which is copied as soon as the share preview opens, window controls) and the `rbimg://` image cache protocol. `electron/preload.cjs` exposes these to the renderer.
- `src/App.tsx` holds most of the UI (one big file, ~5100 lines). Helpers live in their own modules (`prices.ts`, `priceHistory.ts`, `copies.ts`, `cardmarket.ts`, `cardImages.ts`, `deckHelpers.ts`, `banlist.ts`, `storage.ts`, ...).
- Styling in `src/styles.css`: dark "Apple look", graphite surfaces with amber accent, sidebar navigation. Icons from Lucide (`src/Icon.tsx`).
- No test framework. The `scripts/check_*.mjs` / `check-dopamin.mjs` files are plain assertion scripts. `checks.yml` runs them (every `scripts/check*.mjs`, new ones included) plus `npm run build` on every PR and push to main; the Release workflow runs them again.
- Stefan's PC has no Python (only the Microsoft Store alias), so Python bake scripts run in the GitHub workflows, e.g. `gh workflow run prices.yml --ref <branch>`.

## UI structure

- Sidebar tabs (`Tab` in App.tsx): `collection` is labelled "Sets" (set binders, wishlist, value history); `owned` is "All owned", the owned binder (`binderView === 'owned'`, kept in sync with the tab by an effect) with a set filter (`ownedSet`) a sort select (`ownedSort`: by set, or by the price of one owned copy, foil price when only foils are owned) a Borrowed only toggle (`ownedBorrowedOnly`: only cards borrowed from someone) and a Not needed in decks toggle (`ownedNotInDeck`: `spareCopies(id) > 0`, i.e. `availableForDecks` minus the copies of all decks added up; tiles show "n× spare", capped at the borrowed copies when Borrowed only is on); the toggles combine (AND) and none is persisted. Then Catalogue, Sales, Decks, Borrowed, Stores, Dopamin, Backup.
- Searches and filters (`q`, set / type / rarity / ability / domain filters, owned-binder toggles, `saleQ`, ...) are shared state; a sidebar tab change (`switchTab`) resets them all, programmatic jumps (`openDeck`, alerts) do not. Filter dropdowns (`RarityMenu`, `AbilityMenu`) get `.lang-trigger.filtered` (amber like an active chip) while something is ticked.
- Selling: one dialog (`soldAsk`, type `SoldAsk`, opened by `openSoldAsk(items, source)`, booked by `confirmSale`) for three sources: the cart ("Mark as sold" per tile, or tiles picked with "Select" (`saleSel`, session only, `.sale-selected`) and "Mark n selected as sold" in the cart header; there is no "mark all"), a single card from the sales search (the tick button next to the cart button, `pickerCard`'s `extra`; commission preset 0 because that is usually a cash sale) and the Cardmarket import. Each `SoldItem` lists the card's copy groups (`copyGroups`) with steppers preset by `defaultPicks` (normal first, without details first, then lots from the end) plus "Not (any more) in the collection" (`gone`: logged without cost, collection untouched), and its price per copy (cart: the listing price). `walkSoldItems` runs the items in order, so two orders of one card never take the same copy. Commission % (`CM_FEE_PCT` = 5, Cardmarket's rate for private sellers; `feeFor` rounds it per copy to the cent like Cardmarket, checked against Stefan's transactions) applies to the batch. Postage has two sides (`Postage`, keyed by `postageKey`: once per sale, per shipment for the import): "Postage from buyer" (paid out by Cardmarket without commission, stored as `shipIn`) and "Your postage" (`ship`), so a free letter with 1.25 € buyer postage is a plus. Cards one buyer took together belong in one sale: the dialog lists the other cart cards to add (`addToSoldAsk`, with their cart count; not for the import, which groups by shipment already) and drops a card from this sale with its × (it stays in the cart). `saleEntries` splits a shared postage over the sale's lines by price (by copies when no price is known) with `splitCents`, so every card's profit carries its part and the parts add up exactly. The dialog ends in a receipt: sale price − commission + buyer postage = payout, − own postage − cost = profit. `takeCopies` removes exactly the picked copies from lots and counts; every picked group becomes a `SoldEntry` with its cost (`lotCost`: purchase price or pack share), `fee` and `ship`. Sold copies also leave the cart. The Cardmarket import button is removed until a better export format is found (Stefan, Oct 2026); `parseCmSold`, its check and the dialog's per-shipment mode (`source: 'import'`) stay for it. The import read Cardmarket's "Sold Articles" CSV (`parseCmSold`: fixed column order, product id → card through `cmId` in the price book), skips rows whose `ref` is already in the log and names rows it cannot match. The transactions export (CSV / XLS) only holds sums, so it is not used. The cart panel shows the totals on top (`soldTotals`: revenue, commission and net postage (shown as one signed "Fees & postage" value, its effect on the profit), cost, profit only over entries with price and cost, the rest counts as open) and the sold list under the cart. `scripts/check_soldlog.mjs` covers picks, taking copies, fees, totals, the CSV parser and cleaning.
- Buying: "Add a purchase" (button in All owned, and "Add a purchase with shipping" under My copies in the card detail, which starts it with that card) opens `buyAsk`: one order with seller, day and shipping, card lines (catalogue search `buyHits`, copies, normal / foil, price per copy). `confirmPurchase` adds the copies to `rawCollection` and one bought lot per line whose `buy` is the price plus its share of the shipping (`purchaseLots` / `purchaseCosts` in `src/purchase.ts`, split by price with `splitCents`, covered by `scripts/check_purchase.mjs`). Several sellers are several purchases.
- Sales cart tiles take the user's Cardmarket listing price per copy (`rb.saleAsks.v1`, pruned when a card leaves the cart, in the "sales" backup group); the cart header sums it and the sell export (text and CSV) uses it instead of the trend (`CmLine.ask`). A tile whose copies lack a source (no lot, or bought without a price) shows a "No details" flag in the art (`CardTile` `artFlag`), which opens the card detail. The cart panel scrolls as one and its grid needs 260 px tiles; the search lists on the right are a flex column (as a grid Chromium sized narrow rows to their min-height, so text ran into the next row) and their controls wrap under the card in window mode. The sales search lists the whole catalogue (plain runes left out) with an "Owned only" chip (`saleOwnedOnly`) and `pickerCard`'s `coll` option (the `collectionButtons` steppers) to set owned counts right there.
- Sales tab has two views (`salesView`): the cart (with the sales totals and the sold list) and "Add sources", a stack of owned cards whose copies still lack a source (`unsourcedCopies` in copies.ts: no lot, or bought without a price; pulled counts as done; copies under `REVIEW_MIN_EUR` = 1 € are bulk and left out), most valuable first (`reviewStack`). One card at a time with the `CopyEditor`; `reviewId` pins the card being edited until Next / → (`reviewNext`: done cards count, unfinished ones go to the session-only `reviewSkipped`). The stack is derived from the data, so stopping and coming back needs no stored progress. `reviewPack` is the booster / display that "+ Pulled" fills in (`CopyEditor` `defaultPack`), session only.
- Matchup view (`src/MatchupView.tsx`, `src/matchups.ts`): the "Matchup" button in an open deck's header (only with a Legend) opens a lolalytics style view: the Legend's good and bad matchups against every other Legend (win rate, games, "little data" under 10 games, min games filter 1 / 5 / 10, default 5) and per opponent "Details": counter cards and what that Legend usually plays (`typicalCards`, share of its uploaded decks). Counter cards (`counterCards`) come from decks of every Legend that faced the opponent (one Legend alone has too few games), kept to cards the deck can run (`cardMatchesLegendDomains`, not banned), ranked by a smoothed win rate minus the average of all decks against that opponent (`COUNTER_PRIOR` games of baseline, at least `MIN_COUNTER_GAMES`); each shows "In deck ×n" / owned copies, the share of the own Legend's decks running it (`inLegend`, from `by`) and opens the card detail. Above them the detail has tips: the opponent Legend's ability text (errata first) and its tricks (`typicalTricks`: cards in at least a quarter of its decks whose text starts a line with Hidden, Reaction / Quick-Draw / Ambush or Action, `trickKind`), then "Your deck against" (`deckInMatchup`: the open deck's main and sideboard cards, same smoothing, at least `DECK_NOTE_LIFT` above or below average; better sideboard cards say "bring in?", worse main deck cards "take out?"). One Legend against one opponent rarely has more than a handful of games, so every card number is counted over all Legends. Data: `public/matchups.json`, loaded live from main like the prices, baked by `scripts/bake_matchups.mjs` (workflow `matchups.yml`, daily) from RiftLite's community matrix page (riftlite.com/community/matrix: user-submitted games of the current season, robots.txt allows /community). That page is a Next.js render; `scripts/matchups_parse.mjs` joins the `self.__next_f.push` chunks (scanned by hand, one is ~20 MB, a regex overflows the stack) and reads `matrix.cells` (pooled both directions) and `matches[].deckSnapshot` (the uploader's own deck; cards count by name, Rift Atlas `[CODE]` suffixes stripped, sideboard ignored). RiftLite keys Legends by champion name, or by full name when a champion has several (`legendKey`; a bare "Master Yi" stays unmapped). riftdecks.com has a tournament matrix too, but its robots.txt bars AI crawlers, so it is not scraped. `scripts/check_matchups.mjs` covers parser, ranking, counter cards, tricks and the deck check.
- Da Rules tab (`src/RulesView.tsx`, `src/rules.ts`): the official Core and Tournament Rules from `public/rules.json`, loaded live from main like the prices (bundled copy offline). Search: a rule number finds it and its sub-rules, words match in any order (`searchRules`); clicking a hit's number jumps to it in the full list. `rules.json` is baked by `scripts/bake_rules.mjs` (workflow `rules.yml`, daily): it reads the PDFs linked on playriftbound.com/en-us/rules-hub with `pdfjs-dist` (dev dependency only), `scripts/rules_parse.mjs` splits them into `{ n, t, h? }` (rule start = number at the most common left margin, indented lines continue it, "Example" lines get their own paragraph), and the file is only rewritten when the text changed. `scripts/check_rules.mjs` covers parser and search.
- Backup tab (`src/BackupView.tsx`, logic in `src/backup.ts`, covered by `scripts/check_backup.mjs`): one JSON file `{ app, format, at, version, data }` where `data` holds the raw localStorage strings of every `rb.*` / `riftbound-*` key except caches, the CardTrader token and `rb.backup.*` (`isBackupKey`; new keys are included automatically). `parseBackup` rejects foreign, newer-format or broken files before anything changes. Import replaces only the parts ticked in the confirm dialog (`BACKUP_GROUPS`: collection incl. copy details, decks, wishlist incl. price alerts, sales, borrowed, other = everything else; `backupGroup` maps keys, unknown keys are "other"); nothing is ticked at first and the button stays disabled until something is. Parts that are already identical in app and file (`sameGroup`) say "same", and a note warns when every ticked part is. After the reload the app opens on the Backup tab and names the replaced parts (sessionStorage `rb.importDone`, `importJustDone`). The reload must go through `app:reload` (main process `webContents.reload()`): the window's `will-navigate` lock silently blocks the renderer's `location.reload()`, which left the old state on screen and let later saves write it back. `restoreBackup(store, file, groups)` also removes the chosen parts' keys missing from the file and leaves all other keys untouched, then the app reloads; it first writes a `before-import` backup and aborts if that fails. Files live in `Documents\Deakrix Riftbound Tracker\Backups` or the user's own folder (`backup:chooseFolder`, saved in `backup-settings.json` in the Electron profile, not in localStorage, so a restore never moves it) (`backup:*` IPC in `electron/main.cjs`: temp file + rename, names `<auto|manual|before-import>-<local stamp>.json`, 14 kept per kind). Choosing a folder that already holds backups (the old one after a reinstall) opens the newest in the replace dialog. `autoBackup()` runs at startup, at most once a day; it and the before-import backup are skipped while the app is empty (`isEmptyBackup`), so a fresh install never becomes the newest file. Collection CSV import / export was removed in favour of this; the Cardmarket sell CSV stays.
- Stores tab has three views (`storeView`): Displays (`src/StoreDisplays.tsx` + `src/displays.ts`, the display price comparison), the store map, and Dates (`src/RoadmapView.tsx` + `src/roadmap.ts`: Riot's official dates from `public/roadmap.json`, still-to-come ones by month with a countdown, Germany highlighted; covered by `scripts/check_roadmap.mjs`). The store map comes from the official event search (events.playriftbound.com, the "Events" page): `net:rbEvents` in `electron/main.cjs` POSTs persisted queries (`CompeteTournamentSearch`, `OrganizerSummary`) by their manifest id with Apollo client headers; `eventsToStores` in `src/stores.ts` groups events into stores (covered by `scripts/check_stores.mjs`). The search answers at most ~160 km around a point (a larger distance silently returns the same events), so bigger radii use `searchCircles` (3×3 grid) and All Germany uses `GERMANY_CIRCLES` (5×4 grid) plus `isGermanEvent`; `check_stores` tests that the circles leave no gap. A search returns `StoreSearch` (`truncated` when a page cap or a later page / circle failed), the UI says so. Store pin and distance come from the organizer profile (`organizerContact`, cached per session); a store whose profile does not load still shows with its events. Only the newest search may write its result (`storeSearchSeq`). The ids are pinned: when Riot changes those queries the search fails and the tab says so (`EventSearchError` → `stores.unreachable`, which also names ad blockers / DNS filters: Stefan's own DNS answers 0.0.0.0 for events.playriftbound.com). The event search is the only store source: the old UVS retailer list is end of life and no longer used by the app; new ids are in the events page's query manifest chunk (`"name":"CompeteTournamentSearch"` next to its `"id"`). The home location (`rb.storeHome.v1`) is searched when the view opens. Displays reads `sealed.json`, asks the listed shops again live (Shopify `/search/suggest.json`, WooCommerce Store API, both allowed in `net:fetchJson` only for the fixed Riftbound queries) and CardTrader through `net:cardtrader` with the user's token. Title parsing (display / language / set) exists twice, in `displays.ts` and `scripts/bake_sealed.py`: keep both in sync, `scripts/check_displays.mjs` covers the TS side.
- Borrowed tab: a `BorrowedGroup` without `direction` is lent to that person (copies leave `availableForDecks`); `direction: 'from'` means borrowed from them (copies add to `availableForDecks`, show in All owned with the purple `BorrowedBadge`: one pill per person, "Borrowed from <name> ×n" from `borrowedFromById` / `borrowedInFrom`; when space runs out the prefix is cut first, name and count stay visible, never touch `rb.collection.v1`, value or set progress). When cards changed hands for good, the row's tick / handshake button (or "Kept all" / "Gave all away" in the entry header) settles them after a confirm (`settleBorrowed` in borrowList.ts, deckConfirm kind `settle`): borrowed-from copies join `rawCollection` as normal copies, lent copies leave it (normal first, like a sale; the copy details follow through `fitCopyBook`), and the cards leave the entry. Nothing goes into the sold log. Export / import format is `src/borrowList.ts` (`qty code name` lines; a lent list pasted into an empty entry turns it into "borrowed from"), covered by `scripts/check_borrow.mjs`.
- Deck builder rune section: the search list hides plain runes (`isPlainRune`), those have the per-domain counter. Every other rune is listed: alt art and the Nexus Night runes (set `*-NN`, rarity Showcase, so not plain and not covered by the counters).
- Search lists on the right (wishlist, sales, decks, borrowed) all render through `pickerCard(c, { owns, draggable, note, add })`: same tags line, price boxes, "Owns" column (`.row-stat`, like the deck rows) and add button. Change the look there once, never per tab. Decks pass `availableForDecks` as owns, the others the owned count, and the deck search also passes `inDeck` (copies already in the open deck, an "In deck" column). The tags line shows "In <deck> ×n" pills for every deck using that print (`decksByCard`, click → `openDeck`); the deck search replaces them via `tags` with `otherDeckPills` (other decks, any print).
- Keywords in the card detail come from the rules text (errata first) plus the baked `card-keywords.json`. Never detect them from the card name ("Thrill of the Hunt" is not Hunt).
- Card tiles are `CardTile`; list rows are `.list-item` (`.deck-card-row` in decks and borrowed, `.picker-card` in the search panels on the right). Clicking a tile or row opens the card detail unless the click hits a button or input (`isControlClick`). The detail's prev / next (`lbNav`, buttons beside the panel, ← → or A D) only exist in the card grids: All owned, a set binder, the catalogue and the sales cart; search lists (`.picker-card`) and every other view get none.
- Deck usage: `decksByCard` maps a card id to `DeckUse[]` (deck id, name, copies over all sections). On tiles each deck is an `.in-deck-flag` badge ("Deck ×n") stacked in the art's top right `.flags` (more than three decks: two badges and "+N decks", which opens the card detail); the card detail shows the same as `DeckUses` pills. All of them call `openDeck(deckId)`, which closes the detail, switches to Decks and expands that deck.
- Card tile layout: set / ban / errata pills in `.card-tags` on their own line under the name, borrowed pills in `.borrowed-tags` (one line each), then prices and the normal / foil counters in `.tile-foot`, pinned to the bottom so they line up across a grid row. Deck rows put their pills in a `.card-tags` line under the name too, so the name keeps the full width in window mode.
- Prices: `PriceBits` is the only price display, `.price-boxes` with a small label over the value (From / Ø30 / Foil; foil only cards get one Foil box). Tiles stretch the boxes, list rows (`.list-item .price-boxes`) keep them compact and wrap. The card detail uses the bigger `.card-price-tiles`.
- Drag and drop: search cards set `text/riftbound-card`; Chromium drops or shrinks a native drag image, so `onPickerDragStart` sets an invisible one (`EMPTY_DRAG_IMAGE`) and the app draws the big preview centred on the pointer (`dragGhost`, moved by a document `dragover` listener, cleared on drop / dragend; `.card-float-preview` has `pointer-events: none`, so drops still reach the target) and drop into deck sections, wishlist, sales cart and borrowed (`onSectionDrop`, `cartDrop`, `onBorrowDrop`). Cards in those lists drag out with `removeDragProps` (`text/riftbound-remove`): a drop outside the panel marked `data-remove-src` removes one copy.
- Plain runes (`isPlainRune`: rune and not foil only) are not tracked. The stored `rawCollection` keeps whatever users entered (nothing is deleted); `collection` = `withoutPlainRunes(rawCollection)` is what the whole app reads, so value, set progress (`setCards`, `rarityBySet`), All owned, sales and borrowed never see them. Save, the foil fold and `fitCopyBook` work on `rawCollection`. Catalogue tiles of plain runes show "not tracked" instead of counters, `collectionButtons` returns null for them, rune tiles show no Owns, and `deckCoverage` treats plain runes as always covered.
- Prints of one card: `cardKey` (name + subtitle + types, in deckHelpers) groups alt art, overnumbered, signed and reprints (`printsByKey`, plain runes left out, so an alt art rune never counts as a plain one). Deck ownership uses the whole group: `poolAvailable` for the Owns number in the deck search; a deck row shows its own copies plus the spare copies of other prints that `coverDeckLines` gives it, so several prints of one card in a deck never count the same copies twice. Under it "n× in other prints" (`.prints-pop`) shows the other owned prints on hover / focus as art tiles (thumbnail with owned count, set tag, name; hides after a short grace so the pointer can move in, and stops the row's floating card preview while inside), opens upward when the deck list has no room below (`placePrintsPop`), each jumps to All owned with its code as the search (`showInOwned`, which sets `binderView` too, else the tab sync effect clears the search); `deckCoverage` → `coverDeckLines` (deckHelpers, own print first, then spare copies of other prints, `scripts/check_decks.mjs`) for short rows, the Still missing list and the missing value. `otherDeckPills` tags deck rows and deck search cards with the other decks using any print of the card (red when the group's copies do not cover all decks). The All owned "Not needed in decks" filter still counts per print. Deck sections list prints of one card together (`groupPrints`: deck order, but every print right after its first one), and the share image merges them into one tile with the copies added up, showing the print with the most copies (an alt art / overnumbered / signed print wins a tie) (`mergePrints`, over champion + main deck and the sideboard). `check_decks` covers both.
- Deck limits: the 3 copy limit counts per `copyName` (full name with subtitle, so "Evelynn, in Control" and "Evelynn, Entrancing" are separate; prints of one card share it), used by `canAddToSection` and `sanitizeDeckCards`. `parseDeckImport` reads a trailing `[CODE]` (Rift Atlas style) through `resolveToken` when the card fits the section, else falls back to the name (a missing comma still matches). `scripts/check_decks.mjs` covers both.
- Deck rows: Collection panel (normal / foil steppers, `collectionButtons`) and Owns / Need. The "Still missing" list groups by set and exports a Cardmarket wants list. Runes show one counter per Legend domain.
- Dopamin (`src/Dopamin.tsx`, `src/dopaminPacks.ts`): pack layout from Riot's Radiance overview, rates as constants with their source in `dopaminPacks.ts`. Slots without a published rate (token / alt rune, foil split) set `estimate` and the UI says so. `scripts/check-dopamin.mjs` checks layout and simulated rates.
- Check `styles.css` before naming a new class. Reusing an existing name (e.g. `.deck-stat`, the deck header value tiles) silently pulls in its styles.
- To look at a UI change, load `dist/index.html` in a hidden Electron `BrowserWindow` with a throwaway `userData` dir, seed localStorage, click via `executeJavaScript` and save `webContents.capturePage()` (register an `rbimg` handler that forwards to `net.fetch` so card art loads).

## Data files (public/)

- `cards.json`: all cards (type `Card` in `src/types.ts`). Legends are stored like champion units: `name` = champion, `subtitle` = title ("Rengar" / "Pridestalker"), taken from the Cardmarket product names; `check_decks` asserts every legend has a title. Old deck lists naming a legend by title alone still import (`matchCardByName`), and legend errata are keyed "champion, title". Images point at Riot's official gallery; `scripts/bake_images.py` (workflow "Bake card images") swaps in official art.
- `prices.json`: Cardmarket prices from the public daily price guide (`downloads.s3.cardmarket.com`, game 22: low, 30 day avg, trend, foil; no max), matched by `cmId` (Cardmarket idProduct). Rows without a `cmId` are matched by expansion and name only when exactly one product fits: Cardmarket's V1/V2/... do not follow idProduct order, so never pick a print by V number. Cardmarket only versions a URL (`Name-V1-Rare`) when the expansion holds several products with that name, so `drop_needless_versions` in the bake strips the suffix when the name is unique there (ids in `cm_url_overrides.json` are hand-checked and kept). `sanitize_prices.py` drops zero values, outliers and placeholder asks of 5000 EUR+ with no sales. Cardmarket product pages answer scripts with 403, so links can only be checked against `products_singles_22.json`.
- `cmUrl` is stored canonical (`/en/...?language=1`). The app builds the real link per click in `cmLink`: site locale from the app language, `sellerCountry=7` (Germany) and `language=1` (English copies). The app loads it live from `raw.githubusercontent.com/.../main/public/prices.json` at startup (cached as `rb.prices.remote.v1`), falling back to the bundled copy. New prices therefore need no release, only a push to main. Prices have no per-language split, so a copy's language does not change its value.
- `sealed.json`: display prices for the Store tab, baked daily by `scripts/bake_sealed.py`: Cardmarket price guide rows for sealed products (`products_nonsingles_22.json`, set learned from the singles' idExpansion), the German shops that answer an open product search and their display offers. Shop candidates are `ONLINE_SHOPS` plus the websites in the organizer profiles of German stores with upcoming events in Riot's event search (same persisted queries and ids as `net:rbEvents`, `GERMANY_CIRCLES` and `isGermanEvent` ported from `src/stores.ts`: keep them in sync), so a store without upcoming events drops out until it posts one. When the event search fails, the bake keeps only `ONLINE_SHOPS`. Loaded live from main. The Cardmarket API takes no new private apps; CardTrader has a real API but needs each user's own token.
- `matchups.json`: Legend matchups and counter card counts from RiftLite (see Matchup view), loaded live from main.
- `roadmap.json`: Riot's official dates (set releases, Pre-Rift weeks, Summoner Skirmish, Regionals, Continentals, Showdown Series, conventions) from the playriftbound.com roadmap article, kept by hand (the article is free text, a scraper would break with every redesign). Loaded live from main through `loadLiveJson` (`src/liveJson.ts`, also used by the rules), so a new date needs a commit to main, not a release. When Riot posts a new roadmap, update the items and `updatedAt` / `source`; `check_roadmap` validates the file.
- `price-history.json`: one snapshot per price update, also loaded live from main. Drives the Wertverlauf view (`src/ValueHistory.tsx`).
- `card-errata.json`: official errata keyed by lower case card name. Baked by `scripts/bake_errata.mjs` from playriftbound.com articles (add new articles to `PAGES`). Shown as a blue "Errata" pill next to the ban badge and under the card in the detail view.
- `card-keywords.json`, `sets/`, `packs/`, `displays/`, `domains/`, `symbols/`, `flags/`: static assets.
- `thumbs/`: WebP thumbnails, gitignored. Baked by `scripts/bake_thumbs.py` in the Release workflow and shipped in the installer.

## Card images

- Grids use the bundled thumbnails from `public/thumbs/` (only when `thumbs/index.json` says the source URL still matches the card's image).
- Full art goes through `rbimg://card/?u=<url>`, which the Electron main process caches on disk.
- Grids are lazy. Speed matters more than app size or memory: Stefan and his users run high-end PCs, so prefer caching and preloading over saving space.

## localStorage keys

Keep these keys and their shapes backward compatible. Users' collections live here, and there is no server.

- `rb.collection.v1`: `{ [cardId]: { qty, foil } }`. Don't change this shape. May still hold plain rune counts from older versions; the app ignores them.
- `rb.copies.v1`: per-copy language, condition and purchase price (`src/copies.ts`), layered on top of the collection counts. A lot can carry `pulled: true` (opened from a pack: no `buy`, counted in the value) and then optionally `pack: { kind, eur | null }` with `kind` one of `PACK_KINDS` (booster, display, prerift, boxset, vault, precon): `lotCost` gives each copy its share (`packShare` = price ÷ `PACK_CARDS[kind]`, the tracked cards in that product, plain runes left out; counts and sources in copies.ts), so pulled copies with a pack price count in paid / profit and those without stay out; older lots simply lack the fields. `copyGroups` puts `lotCost` into `CopyGroup.buy`, so invest, sales and the editor all use it. In `CopyEditor` copies without details have Bought / Pulled buttons that turn all of them into one lot (`assign`). Lots entered with "Add a purchase" also carry `from` (seller) and `at` (day), shown in the editor. `splitLot` moves one copy into its own lot (a pulled lot's copy stays pulled, without the pack) so copies can have different prices.
- `rb.backup.v1`: automatic backup.
- `rb.backup.csvReplace.v1`: `{ at, file, collection, copies }`, written by the old CSV import (up to v0.9.34) right before it replaced the collection. Nothing writes it any more; left in place, never deleted.
- `rb.decks.v1`, `rb.wishlist.v1`, `rb.wishTargets.v1` (price alert targets), `rb.wishAlertsSeen.v1`, `rb.sales.v1`, `rb.saleAsks.v1` (`{ [cardId]: eur }`, Cardmarket listing price per copy), `rb.soldLog.v1` (`SoldEntry[]` from `src/soldLog.ts`: `{ id, at: YYYY-MM-DD, cardId?, name, foil, n, eur, cost, pulled?, note?, fee?, ship?, shipIn?, ref? }`, money for all n copies, eur / cost null when unknown, `ref` = "cm:<shipment>:<product>:<price>" for imported rows; in the "sales" backup group), `rb.borrowed.v1`, `rb.poolHidden`, `riftbound-lang`.
- `rb.storeHome.v1`: the store search home location, a plain place string.
- `rb.dopamin.v1`: Dopamin counters per set, `{ [set]: { packs, spent, value, best?: { id, eur } } }` (Cardmarket trend for packs and cards).
- `rb.displayTargets.v1`: max display price, `{ [set or "SET:LANG"]: eur }` (English uses the plain set code). `rb.cardtrader.token.v1` (the user's CardTrader token) and `rb.cardtrader.blueprints.v1` (3 day cache of CardTrader display blueprints).

If a shape has to change, add a new versioned key and migrate from the old one.

## Workflows (.github/workflows)

- `release.yml` (manual, "Run workflow"): runs the check scripts, bakes thumbnails, builds the installer on windows-latest and publishes the GitHub release `v<package.json version>`. **All releases go through this workflow.** Claude cannot create releases directly (403). To release: bump `version` in `package.json` on main, then start the workflow (`gh workflow run release.yml` or via the GitHub MCP).
- `prices.yml` (daily 04:00 UTC + manual): `bake_prices.py` (Cardmarket's public price guide for game 22, no secret) and `bake_price_history.py`, then `bake_sealed.py` (may fail without blocking prices), commits `prices.json`, `price-history.json` and `sealed.json` to main.
- `rules.yml` (daily 04:30 UTC + manual): `bake_rules.mjs`, commits `public/rules.json` when the official rules changed.
- `matchups.yml` (daily 04:45 UTC + manual): `bake_matchups.mjs`, commits `public/matchups.json` when RiftLite's numbers changed.
- `checks.yml` (every PR, pushes to main except the daily data commits, manual): `npm run build` and all `scripts/check*.mjs` on ubuntu-latest.
- `thumbs.yml`: checks thumbnail baking on PRs that touch `cards.json`.
- `bake-images.yml` (manual): official Riot card images into `cards.json`.

The cloud sandbox proxy blocks the card image hosts and playriftbound.com, so image and errata baking runs in workflows (or errata get added by hand).

One-off scripts no workflow runs: `bake_rules_text.py` (rules text from the playriftbound.com card gallery into `cards.json`), `bake_rad_cm.py` (maps RAD cards to Cardmarket products, uses `cm_rad_slugs.json`), `rebake_cm_urls.py` (rewrites `cmUrl` to the canonical English form, uses `cm_url_overrides.json`).

## Conventions

- Commit messages: `vX.Y.Z: short summary` for releases, plain summary otherwise.
- Work on a branch and open a PR. Merge and release only when Stefan says so ("merge und release"): then bump the version, `gh pr merge <n> --squash --delete-branch`, and start `release.yml`.
- Cardmarket export: wants list as text, sell list as CSV with `idProduct` and the own listing price per copy (`CmLine.ask`), else the trend minus the condition discount (`src/cardmarket.ts`). The sell export and the cart value split each card with `saleSplit` (normal first, then foil), the same rule "Mark as sold" uses (`subtractOwnedCopies`), so a foil is never exported as a normal copy.
- Fan project, not affiliated with Riot Games or UVS Games. Domain icons are drawn for the app, not Riot's artwork.
